# THOOOK × PLAGUE: mainnet launch evidence

## Forwardable version

The magic is in the transaction, not in a Meteora graduation or an aggregator listing. XEEu is a Token-2022 mint whose live TransferHook points to a Pinocchio program. We initialized a real Orca Whirlpool V2 pool against WSOL, funded a live LP position, and sent a real `SwapV2` buy. That swap included the hook's extra accounts, invoked the hook, and settled **0.005 WSOL for 1,990.797730128 XEEu**. A separate buyer repeated the trade successfully. We then migrated two more rescued mints, 5oCp and DZVf, in atomic transactions that bought through Orca and checked transferred under the new hook. The XEEu pool is under a custom Orca config and is currently omitted from Orca's public pool API; Jupiter currently says the token is not tradable. OKX finds this exact pool and quotes it but its routed transaction fails because it omits hook accounts. A router or direct wallet UI must build the V2 instruction with those accounts. This proves hooked mints can trade through the Whirlpool program while their hooks are live, not that every retail router already supports them.

## What the trade proves, and where the route stops

The Whirlpool program accepts `TransferHook` mints through V2 instructions when a TokenBadge exists in the chosen config and the transaction includes the mint hook's `ExtraAccountMetaList` accounts. This is a live onchain path. It does **not** require Meteora.

It does not yet establish normal paste-the-CA buying on Orca's site or through Jupiter. More than ten minutes after pool initialization, Orca's public `GET /v2/solana/pools/{address}` still returned `404 Whirlpool not found` for the custom-config XEEu pool. Jupiter's quote API returned `TOKEN_NOT_TRADABLE` for SOL → XEEu, and the same result for 5oCp and DZVf. Orca's public API returned 404 for the existing custom pools used to buy 5oCp and DZVf as well. Orca's default config has no XEEu TokenBadge, so we cannot present this as a default-config pool. A direct buyer must use a wallet transaction assembled with the correct V2 remaining accounts; the [project site](https://thoook.fly.dev) has a live wallet-signed direct buy for XEEu, independently validated on mainnet.

Titan Pro can display an XEEu chart and a token panel, but its current swap request returned `No acceptable routes found` (`-7`). Its enabled providers reported `NoRoutesFound` or `SimulationFailed`. Displaying a chart is separate from generating a valid buy transaction.

OKX's token page also displays XEEu market data, and its quote response identified this **exact** `9zST...pkdfa` Whirlpool as the 100% route. But its generated transaction omitted the hook accounts. An independently decoded/simulated unsigned OKX quote failed at Whirlpool `SwapV2` with `NoExtraAccountsForTransferHook` (6050). The user subsequently sent an [OKX routed transaction](https://solscan.io/tx/4nQJS9uqAiecKtq1vXsJSiyLRFR93pxz852DoDEtbewSZ3h5XnvGtfxL2iHyVvgHNA19pNBmNhaHA5yZzhghkawK), and its finalized onchain logs show the same 6050 error at our pool. Pool discovery and quote display are therefore working at OKX; its transaction builder is not currently producing a valid hooked swap. The failed transaction's token transfers reverted atomically; the network fee was charged.

Fluxbeam's [attempted direct `SwapV2` buy](https://solscan.io/tx/Z3ezWw6pJ5sTit5LRCuk2DVxyzS5Mz8bajnCS3YcmVvs9PF4xBtfbGV9JttqfBUJMRFjxSiqztaAMMpRWL7pq7T) also reached our Whirlpool and failed with 6050. RPC at confirmed slot 453991526 reports `NoExtraAccountsForTransferHook`, a transaction error at instruction 5, and a 455,658-lamport network fee. Its `SwapV2` had `remaining_accounts_info: null`; the THOOOK program was never invoked. This is an instruction-construction failure, not an absence of liquidity. No swap token balances changed.

The launch is control over **our authorized hook pointers and programs**, not an exclusive claim over all Solana hooked tokens. Anyone can create another hooked mint or implement a compatible router. Three of the five rescued mints are now set to THOOOK and have succeeded in real checked transfers; XEEu has the new, funded WSOL pool. `7C95...` has a hook authority outside our control, while `DL8C...` has no TransferHook extension.
